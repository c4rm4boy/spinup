🚀 How SpinUp is built

Everything runs on your own PC. A few web pages talk to a small local helper; the helper runs Claude Code in two modes (quick one-shot calls, and long-lived sessions for each Pro), and Claude Opus does the thinking. Nothing has a server in the cloud except the model itself.

🤖 Claude Code, in two modesthe same tool developers use, run without a window

1 · One-shot calls (staffing, plans, setup)

  • Run from an empty folder, with no tools, no MCP servers, no settings files and no hooks.
  • A fixed system prompt; the answer must be one JSON object, checked by the helper (one retry if it isn't).
  • Extended thinking off: same quality here, a third of the wait.
  • Typical: Lead ~6s, team ~20s, plan ~15s.

2 · Pro sessions (each Pro, and the Lead)

  • A real, resumable session per Pro: each message resumes it, runs once and exits. Idle Pros cost nothing.
  • Each Pro works in its own folder, outside the project's code, and can't see anything else.
  • Tools: read and write in that folder, plus web search. No shell, no email, no other files. Tested: reads and writes outside were blocked by the tools themselves.
  • Typical reply: 4 to 10 seconds.

🛡 Guardrails, by design

Local first. Pages, helper, library and Pro folders are all on your PC. Only the model is in the cloud.
Draft-only. No Pro can send, buy, book or sign. It isn't just told not to; it has no tool that could.
Sandboxed Pros. Each works in its own folder, with no shell, no email and no access to your other files.
Locked-down calls. Staffing and planning calls get no tools at all, and their answers are validated before rendering.
This PC only. The helper listens on 127.0.0.1 and refuses requests from other websites.
Every token logged. Each call is logged with the step, model, tokens and cost.
